# LLMarkers

Data, analysis, figures, formalization, and manuscript sources for the
LLMarkers paper.

## Setup

This repository is a `uv` project. From the repository root:

```bash
uv sync --locked
```

Run Python entry points with `uv run`, for example:

```bash
uv run --locked python analysis/build_fig2_marker_recovery.py
```

## Repository Layout

```text
analysis/                  Analysis code, data-processing scripts, formalization, and figures
analysis/artifacts/        Generated TSV, Markdown, and table artifacts
data/                      Benchmark, bioRxiv, HCA, CAP, and manual-paper inputs
docs/                      Static browser, papers, and related notes
docs/paper/biorxiv/        Active bioRxiv manuscript, supplement, figures, and manifest
docs/paper/submissions/    Venue-specific submission packages
docs/notes/                Related design notes and schema documentation
analysis/formal/           Lean formalization of marker identifiability claims
```

## Manuscript Figure Pipeline

The manuscript imports LaTeX figure wrappers from
`docs/paper/biorxiv/tex-figures/`. Figure 1 is native TikZ. Figures 2 and 4
assemble panel PDFs generated by the two active figure scripts:

```bash
export MPLCONFIGDIR=.mplconfig
uv run --locked python analysis/build_fig2_marker_recovery.py
uv run --locked python analysis/build_cap_liver_local_global_deg.py
bash analysis/render_paper_standalone_figures.sh
```

The CAP command requires the two AnnData files described below. Figure 3 is
generated by `analysis/analyze_mrkr_corpus.py`; its complete database restore
and analysis commands are in the Source-Grounded Corpus section. Figure
dependencies and result files are listed in
`docs/paper/biorxiv/figure_manifest.md`.

The CAP liver panels require two large AnnData files that are not tracked in
git. Download instructions, byte counts, and SHA-256 checksums are in
`data/cell_annotation_platform/anndata/README.md`.

Build the manuscript and supplementary note from the bioRxiv submission directory:

```bash
cd docs/paper/biorxiv
latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
latexmk -pdf -interaction=nonstopmode -halt-on-error supplementary-note.tex
```

## Core Data

The curated benchmark lives under the seven study directories in `data/` and
links each reported marker to manuscript evidence and DEG context.

Large text-mined marker corpora live under `data/biorxiv/` and `data/hca/`.
The current cross-paper results are generated from the validated corpus
archive described below. CAP marker inputs and provenance are documented in
`data/cell_annotation_platform/README.md`.

Large CAP AnnData downloads are intentionally ignored by git. Their source
URLs, checksums, and expected filenames are recorded in
`data/cell_annotation_platform/anndata/README.md`.

## Source-Grounded Corpus

[`mrkr`](https://github.com/sbooeshaghi/mrkr) converts one manuscript into a
validated `paper.onto.json`. This file links exact source evidence to marker
genes, target cell types, stated comparisons, tissues, and ontology terms.
Each claim also carries one organism term, and extraction is scoped to the
organism declared in the source manifest.
LLMarkers owns the corpus runner and normalized database built from those files.
The default runner expects a sibling `mrkr` checkout. Use `--mrkr-cwd` to point
to another checkout. The runner fingerprints the complete `mrkr` package,
prompt, gene map, project file, and lockfile in each status record.

The validated benchmark was produced with the revision recorded in
`analysis/mrkr.lock`. Reproduce that tool environment with:

```bash
git clone https://github.com/sbooeshaghi/mrkr.git ../mrkr
git -C ../mrkr checkout c0e33d6d1450f3e80c1adb3ccdf892b225cb748e
uv sync --project ../mrkr --locked
```

Source manifests include the organism explicitly. The packaged human
`gmap.txt` resolves aliases after prioritizing canonical Ensembl gene symbols.
Another organism requires a versioned species-specific map in `mrkr`.

Inspect the fixed seven-paper benchmark without making API calls:

```bash
uv run --locked python analysis/mine_corpus.py \
  --manifest analysis/benchmark_sources.tsv \
  --out analysis/artifacts/mrkr_benchmark_v1 \
  --dry-run
```

Run one paper before increasing the scope:

```bash
uv run --locked python analysis/mine_corpus.py \
  --manifest analysis/benchmark_sources.tsv \
  --out analysis/artifacts/mrkr_benchmark_v1 \
  --limit 1 --jobs 1
```

Run the complete bioRxiv and HCA source set with:

```bash
uv run --locked python analysis/mine_corpus.py \
  --corpus both \
  --out ../mrkr_build/corpus_onto_v2 \
  --jobs 6 \
  --allow-partial
```

The runner skips source-matched, validated papers when the same command is
repeated. After API retries are exhausted, recover papers with localized claim
validation failures using:

```bash
uv run --locked python analysis/repair_corpus.py \
  --out ../mrkr_build/corpus_onto_v2
```

The repair step does not call an LLM. It drops only claims that failed exact
source validation and gene terms whose label conflicts with the cited source
text. Each change is recorded in `paper.claims.repair.json`, and repaired
documents must pass the same grounding and validation commands as unmodified
documents.

Successful runs write a portable `onto_manifest.tsv`. Build a database without
ontology hierarchy expansion as follows. Here, `--exact-only` means that the
closure table contains identity edges only; unresolved and coarse term records
remain available for audit.

```bash
uv run --locked python analysis/build_claim_db.py \
  --manifest analysis/artifacts/mrkr_benchmark_v1/onto_manifest.tsv \
  --out analysis/artifacts/mrkr_benchmark_v1/claims.sqlite \
  --exact-only
```

The source manifest, generated ontology manifest, artifact hashes, organism,
`mrkr` source fingerprint, and validation status are separate parts of the
audit trail. The validated claim and onto JSON files are durable semantic
artifacts. The SQLite file is derived and can be rebuilt.

The complete validated corpus run is stored in
`analysis/artifacts/mrkr_corpus_onto_v2.tar.gz`. Verify and unpack it from the
repository root with:

```bash
shasum -a 256 -c analysis/artifacts/mrkr_corpus_onto_v2.tar.gz.sha256
mkdir -p ../mrkr_build
tar -xzf analysis/artifacts/mrkr_corpus_onto_v2.tar.gz -C ../mrkr_build
```

The archive contains all 979 paper records, source and ontology manifests,
per-paper validation provenance, raw model responses, repair reports, and the
derived exact-only SQLite database.

Run the corpus-scale marker reuse analysis from the restored database with a
pinned Cell Ontology release:

```bash
curl -fsSL \
  https://github.com/obophenotype/cell-ontology/releases/download/v2026-06-08/cl.obo \
  -o /tmp/llmarkers-cl-v2026-06-08.obo

uv run --locked python analysis/cache_cell_ontology_labels.py \
  --database ../mrkr_build/corpus_onto_v2/claims.sqlite \
  --ontology /tmp/llmarkers-cl-v2026-06-08.obo \
  --source-url https://github.com/obophenotype/cell-ontology/releases/download/v2026-06-08/cl.obo \
  --out-dir analysis/artifacts/mrkr_corpus_analysis_v1

uv run --locked python analysis/analyze_mrkr_corpus.py \
  --database ../mrkr_build/corpus_onto_v2/claims.sqlite \
  --source-manifest ../mrkr_build/corpus_onto_v2/source_manifest.tsv \
  --ontology-audit analysis/artifacts/mrkr_corpus_analysis_v1/cell_ontology_label_audit.tsv \
  --out-dir analysis/artifacts/mrkr_corpus_analysis_v1 \
  --repo-root .
```

The primary reuse analysis combines mapped positive markers into one reported
marker gene panel for each normalized cell type label in each paper. It requires
at least three genes per panel. It excludes pairs from the same normalized
article title and compares two papers that use the same cell type label with
collection- and marker-count-bin-matched papers that use different labels.
Negative markers are written separately. Ontology-level recurrence uses
only reported labels equal to a Cell Ontology canonical label or exact synonym;
the OLS full-text-coverage flag alone is not treated as semantic equivalence. Results,
definitions, sensitivity checks, and the interpretation boundary are recorded
in `analysis/artifacts/mrkr_corpus_analysis_v1/report.md` and
`run_metadata.json`.

The benchmark manuscript text is not redistributed because of source-license
restrictions. A clone can validate the committed artifact hashes and rebuild
the database. Re-extraction and exact source-text validation require the manuscript
files listed in `analysis/benchmark_sources.tsv`.

The database includes the `marker_evidence` view and the `profile_markers` view,
which groups marker genes by paper and cell type label. For example, this query
returns source evidence for one marker:

```sql
SELECT paper_key, target_label, gene_symbol, direction, span_literal
FROM marker_evidence
WHERE gene_symbol = 'CD3D';
```

The original human annotations remain the benchmark ground truth. Build the
source-specific benchmark representation without modifying those files with:

```bash
uv run --locked python analysis/build_benchmark_evidence.py \
  --manifest analysis/benchmark_evidence_sources.tsv \
  --output-dir analysis/artifacts/benchmark_evidence_v1
```

Text and image annotations become separate, `mrkr`-shaped evidence documents.
Unfiltered DEG rows remain quantitative differential-expression results rather
than reported marker statements.
The manifest also separates the seven primary ground-truth files from the
archived Emont backup. `reconciliation.json` verifies that every source row
round-trips exactly once and that no source file changed; `review.tsv` exposes
non-exact text anchors and duplicate legacy rows without changing them. See
`docs/notes/benchmark_evidence_schema.md` for the schema and migration rules.

Compare the organism-aware `mrkr` benchmark run with the source-specific human
annotations using:

```bash
uv run --locked python analysis/compare_mrkr_benchmark.py \
  --mrkr-root analysis/artifacts/mrkr_benchmark_pilot_20260721 \
  --benchmark-root analysis/artifacts/benchmark_evidence_v1 \
  --legacy-results analysis/artifacts/fig2_llm_recovery.tsv \
  --out analysis/artifacts/mrkr_benchmark_pilot_20260721/comparison_v2
```

The comparison reports gene-only, source-anchored gene, exact target-label--gene,
and text-plus-image results separately. Positive and negative extracted markers
remain distinct because the human benchmark contains only positive associations.

The DEG-source linkage test is an analysis experiment, not part of the `mrkr`
record contract. It takes the validated claims above and asks the LLM to select
one paper-specific DEG `data_id` from the source catalog in the converted
benchmark. Run the API-backed experiment with:

```bash
uv run --locked python analysis/evaluate_mrkr_deg_linkage.py \
  --mrkr-root analysis/artifacts/mrkr_benchmark_pilot_20260721 \
  --benchmark-root analysis/artifacts/benchmark_evidence_v1 \
  --out analysis/artifacts/mrkr_benchmark_pilot_20260721/deg_linkage_v1 \
  --run-llm --env-file .env
```

This sends the exact extracted source text, normalized marker terms, and DEG
source catalog to Anthropic; it does not send full manuscripts or expression
matrices. `ANTHROPIC_API_KEY` and, optionally, `ANTHROPIC_MODEL` must be present
in the environment file. Omit `--run-llm` to reevaluate existing linkage
artifacts without making API calls. The report separates end-to-end
`(data_id, target, gene)` F1 from conditional linkage accuracy among marker
claims already matched to human evidence. In the fixed seven-paper run, the
LLM selected a curator-associated DEG source for 82 of 91 evaluable claims;
the exact target-label baseline selected 28 of 91. The committed term-level
review remains available for tracing the gene evidence behind each evaluable
claim.

## Website

The static marker browser in `docs/` reads `docs/llmarkers.sqlite` in the
browser.

```bash
uv run --locked python analysis/build_llmarkers_sqlite.py
uv run --locked python analysis/export_minilm_embeddings.py
python3 -m http.server 8000 -d docs
```

Open `http://localhost:8000`.

The MiniLM embedding export downloads
`sentence-transformers/all-MiniLM-L6-v2` on the first run unless the model is
already present in the local Hugging Face cache.

## Formalization

Lean sources in `analysis/formal/` are part of the active manuscript support and should
remain in the main tree. They formalize why local marker separation does not
imply global atlas-scale identifiability.

Build the formalization with:

```bash
cd analysis/formal
lake build
```
